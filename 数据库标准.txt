合同文本生成规范

将本规范与源合同一起交给大模型。按第一至四节生成，按第五节检查。第六节列出当前阅读器的限制。第七节是可以直接保存并导入的完整示例。

一、默认输出格式

1. 每份合同生成一个 UTF-8 编码的 .txt 文件，文件内容是一个标准 JSON 对象。从 { 开始，到 } 结束。导入入口为顶部菜单「导入合同条款 (.txt)」。
2. 顶层直接以条款编号为键，条款字段对象为值。编号和字段名使用 JSON 双引号。每个条款编号只出现一次，重复编号可能被后面的值覆盖。
3. 只输出文件内容。省略 Markdown 代码围栏、说明文字、注释、JavaScript 变量声明、外层包装（例如 "clauses"）和末尾逗号。
4. 按 JSON 规则转义字符串。正文中的双引号写成 \"，反斜杠写成 \\，换行写成 \n。使用 JSON 双引号包裹字段值，避免单引号、反引号或直接在字符串中插入真实换行。

二、条款字段与内容

1. "title" 必填。填写非空的纯文本标题，保留原合同标题用词。原条款只有编号时，可直接用原编号作标题。
2. "content" 必填。填写非空的完整条款原文，保留原文语言、内容、顺序和引用。属于同一条的子款（如 (1)、(a)、(i)）按原顺序放在该条正文内。
3. "translation" 可选。填写对应条款的简体中文译文。
4. "translation_tc" 可选。填写对应条款的繁体中文译文。
5. 四个字段均使用字符串。未提供或未要求生成某种译文时，省略相应字段或填空字符串。提供译文时，保留与原文对应的子款编号和顺序。省略 notes、refs 等其他字段，它们会在导入时被丢弃。
6. 根据源合同提取内容。源合同缺少条款正文、存在重复编号或无编号内容归属不明确时，先请用户确认，再生成文件。保留原编号，禁止自行补造、合并或重新编号。

三、正文排版

1. 原文和译文都可以用纯文本。需要显示段落或换行时，可用 <p>…</p> 或 <br>。有列表或表格时，可用对应的基础 HTML 标签。
2. 加粗和缩进是排版选项。可用 <strong> 保留原有强调，可用 <p style=\"margin-left: 2em;\">(a) …</p> 表示缩进。例子里的 \" 是 JSON 字符串中 HTML 属性双引号的写法。
3. 正文由阅读器按 HTML 渲染。作为普通字符显示的 &、<、> 分别写成 &amp;、&lt;、&gt;。使用基础排版标签，避免脚本和事件属性。
4. 点击条款标题可查看该条译文，同步滚动按条款对应。原文与译文的段落一一对应便于阅读。切换到繁体时，缺少繁体译文的条款会回退到简体译文。

四、可选的合同元数据

默认使用纯 JSON。导入时，阅读器会提示输入合同简称和全称。只有用户要求自动填入名称，且条款编号适合兼容解析时，才在条款对象前添加以下四行。使用实际合同全称和简称替换示例值。

CONTRACT_META:
name: Example Contract
shortName: DEMO
---

四行之后直接接条款对象。字段名和分隔行按上面的写法保留，名称值直接填写。带此文件头的完整文本会走兼容解析。需要自动填入名称时，建议将此格式用于纯数字条款编号。含 1.1、A-1 或其他复杂编号时使用纯 JSON，以免兼容解析漏读。合同简称用于区分合同，相同简称会触发覆盖确认。

五、生成与导入检查

1. 生成前列出源合同中的预期条数和编号。生成后逐一对照，检查编号唯一、条款齐全、标题和正文均为非空字符串，以及原文、子款和引用完整。默认格式的全文应能通过标准 JSON 解析。带元数据时单独校验分隔行之后的 JSON 对象。
2. 将生成结果保存为 UTF-8 的 .txt 文件。打开程序，选择顶部菜单「导入合同条款 (.txt)」。纯 JSON 文件按提示填写合同简称和全称。
3. 在确认框核对合同名称、简称和识别条数。遇到覆盖提示时确认目标合同。条数有差异时先取消导入，检查编号、字段和是否添加了元数据。
4. 导入后对照源合同检查条款编号清单，抽查标题、正文、子款层级和简繁译文。重点检查复杂编号是否都出现，以及导航、编辑和链接能否正确定位。点开关键引用，核实目标合同和完整条款编号。出现漏读时先检查输入格式，出现跳错时按第六节判断引用兼容性。

六、复杂编号与引用限制

1. "1"、"2" 这类纯数字字符串的导航和链接兼容性最好。原合同有 "1A"、"1.1" 等独立条款时，保留完整编号。纯 JSON 可以保留 "1.1"，但书签和右栏翻条的排序、部分编辑操作及自动引用可能受编号格式影响。
2. 同一合同中的 Clause 2 可在主文中链接到已存在的第 2 条。跨合同引用如 GCC Clause 2，需要目标合同已导入，简称和目标条款编号相符。保留原文中的引用，避免为了自动链接而改写法律文本。
3. 主文可识别数字加一个英文字母的引用，例如 Clause 1A。右栏链接和反向引用只识别数字部分，有可能把 Clause 1A 指到第 1 条。Clause 1.1 也可能只链接到第 1 条。Cl. 2 等缩写可能不会生成链接。
4. 同一条款含跨合同链接时，主文可能跳过该条款内的本合同自动链接。以导入后实际打开的目标为准。

七、完整示例

以下示例包含两条条款，演示纯文本、带排版的原文、简繁译文以及 Clause 2 引用。只复制下面从 { 到 } 的内容即可保存为 .txt 并导入。预期识别第 1 条和第 2 条，主文中第 1 条的 Clause 2 应指向第 2 条。

{
  "1": {
    "title": "Definitions",
    "content": "<p><strong>(1)</strong> See Clause 2.</p><p style=\"margin-left: 2em;\">(a) \"Works\" includes A &amp; B.</p>",
    "translation": "<p><strong>(1)</strong> 见第2条。</p><p style=\"margin-left: 2em;\">(a) “工程”包括甲与乙。</p>",
    "translation_tc": "<p><strong>(1)</strong> 見第2條。</p><p style=\"margin-left: 2em;\">(a) 「工程」包括甲與乙。</p>"
  },
  "2": {
    "title": "Payment",
    "content": "Payment is due.",
    "translation": "款项到期。"
  }
}
