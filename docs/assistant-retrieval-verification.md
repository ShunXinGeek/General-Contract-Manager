## 本次改动

- 明确合同简称、编号、字母后缀与子条款；GCC/SCC 分开定位。裸编号有歧义时说明，不强制归入 GCC。子条款问题提供完整父条款，并说明未保证独立定位。
- 明确单一编号走精确路径；综合问题合并当前正文关键词与有效向量，按排名融合。可配置正文重排；失败时保留确定性降级。
- 已知 GCC/SCC 原文匹配才采用静态关系；未知版本只采用当前 SCC 原文明确表达的修改关系。不能确认不等于没有修改。
- 追问只从有效范围内的用户消息恢复指代；重新生成仅使用该消息之前的会话，上下文截断有效。没有增加模型分类/自由改写调用；无法可靠恢复时提示澄清。
- 候选默认20、根条款8、主题最多3、引用一层扩展最多24、正文默认60,000字符；一轮本地补检索，不增加服务调用。主题覆盖判断是关键词启发式，不是语义完整性的证明。
- 完整条款装配超预算时不静默截断，记录遗漏及未完整纳入的修改关系；明确编号受到排序保护，但单条过长仍可能无法纳入，回答须说明缺口。
- 统一提示词：原文、解释、用户事实、条件性适用与待核事项分开；核对主体、触发条件、期限、程序、例外和后果。历史助手回答不作为证据。
- 回答完成后检查本次证据中的合同身份、直接引文与已提供修改的引用；最多一次同模型定向修正，仍失败显示具体提示。校验不判断全部语义、因果关系或法律适用；子条款校验仅能检查标记，不能证明层级位置正确。
- 原生思考参数、流式输出、条款跳转、停止、持久化和跨设备 Key 同步保留；不更换模型、不调整 UI、不修改合同正文。

## 旧索引与资料兼容

记录包含模型、服务空间标识、维度、正文及标题指纹。服务空间仅绑定无凭据的 endpoint origin/path 与模型；不记录 Key，不能证明服务商未在相同模型名下更换内部模型。

缺少元数据、模型/空间不同、维度异常、正文/标题更新或资料删除的向量不参加语义检索。旧数据保留，不伪造当前指纹；降级到当前正文的本地检索，并提示用户主动更新索引。现有预构建向量因此可能被标为待验证，这是预期保护，不是数据丢失。

手动“更新索引”沿用既有在线构建方式，会向配置的 Embedding 服务发送条款；此次没有自动触发全库重建。失败条款计入实际统计；未成功更新的旧记录继续按一致性检查决定是否可用。导出保留新元数据，旧文件仍能导入但不能因此被认定有效。

正文指纹保留标点和大小写，仅归一化 HTML/空白，避免将小数点或比较符号变化认作排版变化。使用非密码学双校验和作缓存一致性检查，不是真实性认证；不同 Markdown/HTML表现形式可能不匹配已知源文，静态关系此时安全降级为未确认，不保证所有同义排版导入都能命中静态表。
