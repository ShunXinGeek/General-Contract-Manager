# 管理助手 Skill 文件规范

适用于通用合同管理助手基础版。文件格式版本为 `1`。

Skill 是可重复使用的合同工作指令。它可以指导助手从本轮材料中查找、筛选和整理条款，并生成索赔报告、信函、对照表或 Mermaid 流程图源码。安装前请按下面的规则编写文件，使用时再提供本次任务涉及的合同与事实。

## 1. 文件格式

- 每个文件包含一个 Skill。文件名以 `.skill.json` 结尾，例如 `claim-report.skill.json`。程序校验后缀时忽略大小写。文件名可以与 `id` 不同。
- 使用 UTF-8 编码，整个文件最多 **32 KiB（32,768 字节）**，包括缩进、换行和 JSON 转义字符。含较多中文的文件可能先达到字节上限。
- 顶层为一个 JSON 对象。字段名和字符串使用双引号。请删除注释、尾随逗号以及复制时附带的 Markdown 代码围栏。字符串内的换行写成 `\n`，双引号写成 `\"`，反斜杠写成 `\\`。
- 当前导入器读取下表中的五个字段。额外字段会被忽略。导入时请直接选择 JSON 文件。标准 `SKILL.md`、文件夹和 ZIP 需要先将其中的名称、描述和指令整理为此格式。

| 字段 | 类型 | 必须满足的条件 | 用途 |
| --- | --- | --- | --- |
| `formatVersion` | 数字 | 必须为 `1` | 标识文件结构版本。 |
| `id` | 字符串 | 1–64 字符，匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$` | 安装身份。使用小写英文字母、数字及分隔用的单个连字符。首尾不能有连字符或空格。 |
| `name` | 字符串 | 去掉首尾空白后为 1–80 字符 | 显示在管理界面、选择列表和已发送消息中。可用中文。 |
| `description` | 字符串 | 去掉首尾空白后为 1–500 字符 | 在管理界面说明用途和适用场景。 |
| `instructions` | 字符串 | 去掉首尾空白后为 1–12,000 字符 | 实际发送给模型的工作指令，可使用纯文本或 Markdown。 |

五个字段均必填，字段名区分大小写。长度按 JavaScript 字符串的 UTF-16 代码单元计数，常见中英文字符通常计为 1，部分 emoji 计为 2。请为不同用途分配不同的 `id`，同一用途的更新继续使用原 `id`。建议也给每个 Skill 起易区分的名称。

## 2. 指令编写要求

`instructions` 应独立说明整个工作流程。模型会收到选中的 `name` 和 `instructions`。因此，关键要求应写进指令正文，`description` 用于给用户说明用途。

1. **明确任务和输入。** 说明需要哪类条款、事件资料或附件，以及最终要产出什么。例如「根据用户提供的事件经过和适用条款，起草一份延误索赔报告草稿」。
2. **定义提取与筛选条件。** 指明要核对的内容，例如责任主体、触发条件、期限起算点、通知方式、例外和后果。需要对比多份合同时，保留各条款的来源，并根据已取得的条文说明补充、替代或冲突。
3. **规定输出结构和依据。** 指定标题、段落或表格列名。用当前来源名与条款号标明合同依据，例如 `GCC Clause 44`。区分条款原文、用户陈述、分析判断与待确认事项。日期、金额、责任或条款依据不足时，用「待补」标记并说明需要什么材料。
4. **明确材料不足时如何处理。** 请助手说明本轮已取得的材料与缺口。知识库只返回当前检索范围内的相关条款，查无结果时写「当前范围未检出」，避免把它当成整份合同没有该规定。
5. **使用可直接交付的文本格式。** 报告和信函可用 Markdown。流程图使用 `mermaid` 代码块，写清节点、分支条件和条款出处。回复结束后，聊天中显示图形并提供「复制源码」。无法绘制时显示源码。

Skill 使用聊天中提供的资料和程序已有的合同检索。文件中的路径、网址或占位符只是文字，程序不会读取配套目录、替换变量、执行脚本或调用外部工具。需要用户补充的信息，可以在指令中写成提问或标成「待补」。安装内容保存在当前浏览器，实际使用时，选中的指令会随本轮问题和材料发送到已配置的 AI 服务。请将合同原文、个人信息和项目机密按需作为本轮材料提供，避免把它们或 API 密钥写进可复用的 Skill 文件。

## 3. 可导入示例

只复制下面代码块**内部**的 JSON，并保存为对应文件名。

### 索赔报告 — `claim-report.skill.json`

```json
{
  "formatVersion": 1,
  "id": "claim-report",
  "name": "索赔报告",
  "description": "依据合同条款和事件资料起草索赔报告草稿。",
  "instructions": "# 工作任务\n根据本轮提供的条款、事件经过及附件，起草一份中文索赔报告草稿。\n\n# 分析步骤\n1. 按时间顺序整理事件，区分用户陈述和有证据支持的事实。\n2. 提取适用条款，核对通知对象、方式、期限和起算点。每项合同依据注明当前来源名和条款号。\n3. 分开分析工期影响和费用影响，写清已知依据及待核事项。\n\n# 输出结构\n按事件经过、合同依据、工期影响、费用影响、待补资料的顺序输出。缺失日期、金额和证据标为「待补」，避免自行推算。"
}
```

使用示例：先通过「引用」加入有关条款，再选择「索赔报告」，输入「请根据这些条款起草延误索赔报告。发包人指示暂停施工，暂停起止日期和费用凭证待补。」

### 合同通知流程图 — `notice-flowchart.skill.json`

```json
{
  "formatVersion": 1,
  "id": "notice-flowchart",
  "name": "合同通知流程图",
  "description": "把通知条款整理为带分支和条款出处的 Mermaid 流程图源码。",
  "instructions": "# 工作任务\n根据本轮取得的条款，整理合同通知流程。先识别触发事件、发出方、接收方、送达方式、期限起算点和例外。\n\n# 输出要求\n使用标记为 mermaid 的代码块输出 flowchart TD。每个判断节点写明判断条件，分支注明各自去向。代码块后按节点列出当前来源名和条款号。缺少依据的期限或分支标注「待核」，并列出需要补充的条款。"
}
```

使用示例：引用通知、送达和期限条款，或开启「知识库」并在问题中写明合同简称和条款号，然后选择「合同通知流程图」发送。

## 4. 安装、使用和更新

1. 打开「管理助手 → Skill 管理 → 导入 .skill.json」。选择文件，检查名称、说明和指令，再点「安装」。新装的 Skill 默认启用。
2. 在聊天中点击「Skill」，或在输入框开头、半角空格或全角空格后键入半角 `/`。列表只显示启用项。继续输入名称或 `id` 可筛选，按 `↑` 或 `↓` 移动，按 `Enter` 选中。按钮显示本轮选择，可打开列表选择「不使用 Skill」来清除。
3. 用「引用」加入指定条款，或开启「知识库」查找相关条款。知识库只检索可见且在检索设置中已勾选的合同。写清问题后用已配置的 AI 模型发送。Skill 指令在检索后加入本轮模型请求，检索范围由现有设置和问题决定。每轮可用一个 Skill，发送后下轮需重新选择。
4. 更新时导入相同 `id` 的文件。有效字段内容相同时显示「已安装相同的 Skill」。内容有变化时预览后点「替换」。替换沿用原来的启停状态。程序为每次新安装或替换记录内部版本，`formatVersion` 继续写 `1`。
5. 在「Skill 管理」中可停用、重新启用或确认卸载。停用或卸载后，已发出的历史消息仍保留 Skill 名称。重新生成旧回复时需要原安装版本仍在本机启用。原版本不可用时，程序会询问是否改用普通问答。

## 5. 验收方法

| 检查项 | 通过标准 |
| --- | --- |
| 文件导入 | 预览显示正确名称、说明和完整指令，点「安装」后管理列表出现该 Skill。 |
| 对话选择 | 「Skill」按钮和 `/` 菜单都能找到该项。选中后按钮显示正确名称，选择命令不会留在已发送正文中。 |
| 材料充足 | 用已知条款和事实试问，核对输出结构、条款出处、日期、金额和分支条件。流程图应能显示图形并复制 Mermaid 源码。 |
| 材料不足 | 刻意少给一项关键条款或事实，核对输出是否标出缺口，并明确需要补充的材料。 |
| 一次一轮 | 发送后按钮恢复为「Skill」，下一轮可以单独选择同一个或另一个 Skill。 |

能安装说明文件通过了程序的格式校验。回答质量还取决于本轮提供的材料、检索结果和选用的模型，请用一组已知答案的合同样例核验输出。若文件能安装但发送时提示超限，应检查整个请求的体积。Skill 指令、历史消息、检索证据和附件共同计入程序的 **2 MiB** 请求上限，模型自身也可能有更低的上下文限制。
